# JiveFetch v0.4.0

日期：2026-09-05

此版本可真实展示独立 video/audio 流的整体下载进度，安全打开已完成文件，并增强 Rust
核心，同时避免 UI 成为第二个状态来源。

## 亮点

- 使用单一且单调递增的任务整体进度，聚合计划中的 video/audio 组件、当前阶段、总大小、
  速度与 ETA。活动任务保持低于 100%；只有验证最终文件后才显示 100%。
- 任务运行时显示本地化的“视频”“音频”“媒体”和“合并”阶段。
- 仅当任务成功完成、非空输出仍存在于所选下载目录中时提供“打开”。路径由 Rust backend
  解析并重新验证。
- 将本地控制与引擎就绪信息合并为紧凑的标题行，同时保留 URL 输入、格式选择器和加入
  队列控件。
- 将内部 string error 替换为 typed validation、storage、engine、scheduler 与 input error；
  仅在 IPC boundary 映射为稳定的本地化消息。
- 将 binary discovery 与 engine execution 分离，并为引擎和进程启动添加窄 test seam，
  同时保留单一 scheduler 与单一 process-tree owner。
- 新增有大小上限的 structured JSON diagnostics，不记录 raw engine line、URL、Cookie、
  browser-profile path 或 output path。

## 验证

- In-place recovery test 覆盖 SQLite schema 从版本 5 到 6 的 migration。
- 常规 Rust suite 从 22 增加到 26 个测试，另有 opt-in real-engine smoke test。
- Release gate 检查格式化、禁止 warning 的 Clippy、frontend typecheck/build、三语文档链接、
  release-note anchor 与秘密扫描。
