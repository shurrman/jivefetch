# JiveFetch v0.3.1

Date: 2026-09-05

This maintenance release makes desktop engine discovery and authenticated YouTube
downloads reliable, and replaces generic failures with actionable explanations.

## Highlights

- Show the JiveFetch version beside the detected `yt-dlp` and FFmpeg versions.
- Probe engine versions from application data instead of the protected Downloads folder,
  preventing a macOS permission race from falsely reporting Homebrew `yt-dlp` as missing.
- Preserve a minimal cross-platform child-process environment while adding standard
  package-manager paths and Deno's user directory. Finder-launched JiveFetch can now expose
  Homebrew Deno to `yt-dlp` for current YouTube JavaScript challenges.
- Classify browser-cookie, authentication, unavailable-media, rate-limit, HTTP 403,
  format, network, and filesystem failures without persisting raw engine output or signed URLs.
- Wait for final process output after exit so short-lived errors are not lost.
- Document `yt-dlp`, FFmpeg, and Deno installation for macOS, Windows, and Linux in English,
  Russian, and Simplified Chinese.
- Explain why replacing an ad-hoc signed macOS build can require granting Downloads or Full
  Disk Access again, and when the Chrome Safe Storage prompt appears.

## Verified macOS scenario

The installed local build detected `yt-dlp` 2026.07.04, FFmpeg 8.1.2, and Deno 2.9.4.
With Chrome selected, `yt-dlp` read the browser cookies, solved the YouTube JavaScript
challenge through Deno, selected the requested media streams, and the download started.

## Install on macOS

The Apple Silicon DMG remains unsigned and unnotarized. Verify its checksum first, then
follow the [macOS installation instructions](../macos-installation.md).

## Compatibility and limits

This release uses locally installed `yt-dlp`, FFmpeg, and Deno. Packages are not signed or
notarized, and managed sidecars are not included. See the [packaging limits](../packaging.md)
and [security model](../security.md).
